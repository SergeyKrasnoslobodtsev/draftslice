# Архитектура: разметка регионов чертежа (region slicing)

Решение по алгоритму разбиения растрового чертежа на регионы (виды, подписи, таблицы) для
последующей нарезки перед OCR и классификацией толщины линий. Проверено и подтверждено
пользователем итеративно в `notebooks/exp_slice_drawing.ipynb` (без отдельного
Researcher/Evaluator - см. "Быстрое прототипирование идей" в `.claude/ORCHESTRATOR.md`).

## Пайплайн

1. **Бинаризация** - `cv2.threshold(gray, 0, 255, THRESH_BINARY_INV + THRESH_OTSU)`.
2. **Dilate** - эллиптическое ядро `cv2.getStructuringElement(MORPH_ELLIPSE, (scale, scale))`,
   `scale = max(width // divisor, 1)`, `iterations=1`, где `divisor` - настраиваемый параметр
   `BinarizationConfig.dilation_kernel_scale_divisor` (дефолт 500, синхронизирован с последним
   проверенным состоянием `notebooks/exp_slice_drawing.ipynb`). Смыкает микроразрывы контура
   детали, подтягивает текст к линиям выносок. Нижняя отсечка `max(..., 1)` нужна для узких
   изображений - без нее `width // divisor` может дать `scale = 0`, и
   `cv2.getStructuringElement` падает с необработанным `cv2.error`; `BinarizationConfig` также
   валидирует `divisor > 0` через `__post_init__`.
3. **Связанные компоненты** - `cv2.findContours(dilated, RETR_CCOMP, CHAIN_APPROX_SIMPLE)`,
   заливка только внешних контуров (`parent == -1`) через `cv2.drawContours(..., FILLED)`,
   `cv2.connectedComponentsWithStats(filled, connectivity=8)` для stats/centroids/labels.
   Контур каждого компонента восстанавливается по одной точке исходного внешнего контура через
   `labels[y, x]` - без повторного `findContours` по маске каждого лейбла. Если во входной
   маске нет ни одного контура (`hierarchy is None`, foreground пуст) - функция обязана поднять
   `ValueError("dilated_mask has no foreground pixels")`, а не падать необработанным исключением
   ниже по стеку и не молча возвращать пустой результат (в блокноте этот случай не встречался и
   решение не было проверено на реальных данных, поэтому явная ошибка безопаснее тихого 0).
   Если несколько внешних контуров (`parent == -1`) маппятся на один и тот же итоговый лейбл
   (случай `RETR_CCOMP`: несвязанная фигура целиком лежит внутри дыры другого внешнего контура,
   заливка дыры объединяет их в одну связную область) - контуром компонента считается тот из них,
   у которого больше `cv2.contourArea` (внешняя рамка, а не случайный вложенный артефакт), а не
   тот, что последним встретился по порядку `findContours`.
4. **Классификация компонентов**:
   - `touches_edge` - bbox компонента касается любой границы изображения (`x1<=0`, `y1<=0`,
     `x2>=width`, `y2>=height`) - артефакты сканирования (точки/кресты/обрезанные линии по краям
     листа), исключаются из пайплайна полностью.
   - `mean_area = mean(areas)` (по всем компонентам, включая touches_edge - фильтр по
     touches_edge применяется только при отборе small/seed, не при расчете самого среднего).
   - `small` - площадь меньше среднего и не touches_edge - кандидаты на объединение в чанки.
   - `seed_labels` - площадь не меньше среднего и не touches_edge - крупные виды/таблицы, seed'ы
     финальной группировки.
   - Если компонентов нет вообще (`len(areas) == 0`) - функция возвращает пустой результат сразу,
     без вычисления `np.mean` на пустом массиве (иначе `RuntimeWarning`/`NaN`).
5. **Объединение мелких компонентов в чанки** - два компонента из `small` объединяются если
   `same_row` (пересечение bbox по Y И зазор по X не больше среднего из их ширин) ИЛИ `same_col`
   (пересечение bbox по X И зазор по Y не больше среднего из их высот). Один проход, без
   раздельных стадий "сначала строки потом колонки" - транзитивность Union-Find протягивает
   цепочку сама. `touches_edge`-компоненты зануляются в итоговой labels-картинке (полностью
   исключены из результата). Сравнение всех пар (`same_row`/`same_col`) считается векторизованно
   numpy broadcasting по массивам bbox, а не вложенным Python-циклом (в блокноте-прототипе цикл
   был безобиден при 8-9 сущностях на лист, в библиотечном коде на плотных чертежах с сотнями
   мелких компонентов это неприемлемо медленно) - последовательным остается только сам Union-Find
   (`union`/`find`) по уже отфильтрованному вектором списку подходящих пар.
6. **Группировка по ближайшему seed'у** - `markers` - labels-картинка, где оставлены только
   пиксели seed-компонентов. `scipy.ndimage.distance_transform_edt(markers == 0,
   return_indices=True)` находит для каждого не-seed пикселя координаты ближайшего seed-пикселя
   (Voronoi-разбиение по seed'ам, честное евклидово расстояние, без площади в формуле). Каждый
   чанк получает группу того seed'а, который чаще всего оказывался ближайшим для его пикселей
   (`np.bincount(votes).argmax()`).

## Почему так (отброшенные альтернативы)

- **Bounding-box кластеризация по dilate+findContours** - отброшена, прямоугольник искажает
  форму невыпуклых деталей.
- **Иерархия контуров (RETR_TREE) без заливки, Canny** - отброшена, Canny дает контур края линии
  а не заливку, мешает анализу вложенности; заменено на простой бинарный порог + заливка.
- **Pairwise area-weighted score (`distance * area_i^p * area_j^p`) + Union-Find по "ближайшему
  соседу"** - отброшена. На реальных данных площадь в любой проверенной степени (1, 0.5, 0.25)
  продолжала забивать расстояние: два одинаково маленьких объекта в разных углах листа выигрывали
  друг у друга, даже когда один из них был в разы ближе к своему реальному крупному соседу; плюс
  одностороннее "ближайший" в Union-Find давало chaining - несвязанные виды склеивались
  транзитивно через общий мелкий узел. Замена на seed + distance transform убрала оба класса
  проблем: расстояние честное евклидово, без веса по площади, Voronoi-разбиение не допускает
  chaining через посредника.
- **Порог small/seed через Otsu по log(area) смерженных чанков** - отброшена, на малом числе
  объектов (8-9 сущностей на лист) Otsu разделяет нестабильно. Заменено на прямое сравнение со
  средней площадью (`mean_area`), которая же используется и для отбора кандидатов на объединение
  в чанки - гарантирует что ничего мелкое не может само стать seed'ом.
- **Фильтрация линий рамки листа через aspect ratio (Otsu по log(aspect))** - отброшена, путает
  тонкую линию рамки с узкими одиночными символами (например цифра "1"), которые тоже имеют
  высокое соотношение сторон но являются легитимным текстом. Заменено на `touches_edge` -
  геометрически надежнее, не путает с текстом внутри листа.

## Модули (src/draftslice/core/region_segmentation)

Пайплайн оформлен отдельным подпакетом `core/region_segmentation/` (не россыпью файлов прямо в
`core/`) - `core` объединяет несколько независимых модулей, каждый в своем подпакете. Имя
`region_segmentation`, а не `region_slicing` - модуль делает семантическую сегментацию
(контуры, классификация, слияние, группировка), а не нарезку на равные прямоугольники, которую
бы честно описывало слово "slicing".

- `binarization.py` - бинаризация и dilate, `BinarizationConfig` (frozen dataclass,
  `dilation_kernel_scale_divisor: int = 500`).
- `connected_components.py` - `ConnectedComponentsResult` + `find_connected_components`.
- `component_classification.py` - `ComponentClassification` (small/seed/edge labels) +
  `classify_components`.
- `region_merging.py` - объединение `small` в чанки (Union-Find по same_row/same_col) +
  зануление edge-компонентов.
- `region_grouping.py` - группировка чанков по ближайшему seed'у через distance transform.
- `pipeline.py` - `run(image_rgb, config=BinarizationConfig())` - композиция шагов 1-6, точка
  входа для CLI. Возвращает `RegionGroupingResult` (`groups`, `group_image`) - только финальную
  карту регионов, без промежуточных артефактов (`BinarizationResult`, `ConnectedComponentsResult`,
  `ComponentClassification`, `merged_labels` вычисляются внутри `run()` и не возвращаются наружу).
  Настраиваемые параметры принимаются через `config`, а не захардкожены внутри модулей. Публичная
  точка входа любого самодостаточного модуля `core` называется `run` (конвенция именования, не
  формальный Protocol/ABC - у разных модулей параметры будут разными, жесткая единая сигнатура их
  бы искусственно ограничила).

  Тот же файл содержит `RegionCrop` (frozen dataclass: group_label, image, left, top, width,
  height) и `extract_region_crops(image_rgb, result: RegionGroupingResult) -> list[RegionCrop]` -
  отдельный метод, не часть `run()`. Принимает исходное RGB изображение и результат `run()`, для
  каждой группы считает bbox по `result.group_image`, вырезает прямоугольный кроп из исходного
  изображения и закрашивает белым пиксели внутри bbox, принадлежащие чужому региону (чтобы в кроп
  не просачивалось содержимое соседних регионов). Нужен для OCR и классификации толщины линий,
  которым нужны реальные изображения регионов с координатами на исходном чертеже, а не только
  карта меток. Не вынесен в отдельный модуль - реализация всего в несколько строк, отдельный файл
  ради этого избыточен.

## Общие модули core (типы, исключения, валидация, image-примитивы)

Решение зафиксировано 2026-09-17 в обсуждении с пользователем: `binarization.py` переименован в
`preprocess.py` (роль шага - препроцессинг, а не конкретная техника бинаризации), однопараметровый
конфиг (`dilation_kernel_scale_divisor: int = 300`) заменил `BinarizationConfig` (dataclass ради
одного поля избыточен), `preprocess_drawing` возвращает только финальную `Mask` после дилатации,
без промежуточного `binary_mask` - публичная функция шага не должна тащить наружу то, что не нужно
следующему шагу пайплайна.

Общие для всех модулей `core` вещи вынесены на уровень `core/` (не `region_segmentation/`):

- `core/types.py` - только универсальные type alias, переиспользуемые в нескольких модулях:
  dtype+shape строительные блоки (`UInt8Array2D`, `Int32ArrayNx2` и т.п.) и собранные из них
  семантические типы (`ImageRGB`, `Mask`, `ImageGray`...). Типы, специфичные для одного шага
  пайплайна (например `ComponentLabelMap`, `ContourPoints`) остаются в модуле, который их
  производит, а не переезжают в `types.py` - иначе он превращается в свалку по тому же принципу,
  по которому `core` не должен быть свалкой файлов.
- `core/exceptions.py` - `DraftsliceException` и наследники `ValueError`/`TypeError`/`RuntimeError`,
  переопределяющие built-in имена внутри пространства имен библиотеки (`except DraftsliceException`
  ловит все ошибки библиотеки разом). Важно: `pytest.raises(ValueError)` со встроенным `ValueError`
  их не поймает, нужен `from draftslice.core.exceptions import ValueError` или
  `except DraftsliceException`.
- `core/validators.py` - `validate_image(arg_name=None, channels=None, dtype=None)`, декоратор
  валидации изображений. `arg_name` не обязателен - если не задан, берется имя первого параметра
  декорируемой функции через `inspect.signature` в момент применения декоратора (не при каждом
  вызове).
- `core/utils/image_utils.py` - переиспользуемые примитивы одной операции над изображением
  (`rgb_to_grayscale`, `binarize_image`, `dilate_image`, `MorphShape`), используются несколькими
  модулями `region_segmentation` вместо приватных копий внутри каждого модуля.

### Строгость типов: граница модуля против внутренней реализации

Решение зафиксировано 2026-09-17. Правило разделяет код по видимости функции, а не по модулю
целиком:

- **Публичная функция** (без `_`, вызываемая из другого файла) - это межмодульная граница.
  Параметры и возврат типизированы через `TypeAlias`/`Annotated` из `core/types.py`, множественный
  результат - `frozen dataclass` (не кортеж), имена параметров длинные и явные, докстринг - полный
  numpy-стиль (Parameters/Returns/Raises). Так же строг `pipeline.py` целиком - он единственная
  точка входа пакета `region_segmentation` наружу и будущего CLI.
- **Приватная функция** (`_...`), используемая только внутри одного файла для разгрузки его
  единственной публичной функции - внутренняя реализация. Допустим словарь CV-сообщества для
  локальных имен (`gray`, `cnts`, `hierarchy`, `kernel`, `labels`, `stats`, `centroids` - это не
  мусорные сокращения вроде `cfg`/`img`, а стандартный словарь самого OpenCV, `cv2.
  connectedComponentsWithStats` в документации так и возвращает `num_labels, labels, stats,
  centroids`). Возврат - обычный кортеж/массив, не обязательно dataclass. Докстринг - одна строка
  или не нужен вовсе, если имя и контекст самоочевидны. Локальная переменная аннотируется типом,
  только если тип не следует однозначно из сигнатуры вызываемой функции.

Обоснование: тяжелая типизация и длинные имена - это осознанное решение проекта ради будущей
библиотеки с CLI, а не идиома CV/Python (в CV-коде и самом OpenCV используются короткие устоявшиеся
имена). Применять эту строгость к каждой внутренней переменной означает переносить чужую
(C#/enterprise) парадигму туда, где у CV-сообщества уже есть свой понятный словарь - оправдано
только на границе, которую видит другой модуль, не читая реализацию.

## Модули (src/draftslice/core/region_segmentation), обновление имени модуля

`connected_components.py` переименован в `component_labeling.py` (решение 2026-09-17) - имя по
технике (`connectedComponentsWithStats`) конфликтовало по смыслу с именем пакета

не переименованы - менялось только имя файла и его внутренняя реализация под правило "граница
против внутренней реализации" выше.
